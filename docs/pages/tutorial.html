Before You Begin — Data Requirements

SCART is designed to be straightforward to use, even if you are new to computational tools. Before running any code, please read these three important rules. They will save you time and prevent the most common mistakes.

⚠️
Rule 1 — Always supply RAW (unnormalised) count data SCART expects raw integer count matrices — the unprocessed output from Cell Ranger or equivalent. Do not supply log-normalised, scaled, or batch-corrected data. Both GEO downloads and any h5ad files you provide must contain raw counts. SCART handles all normalisation internally.
⚠️
Rule 2 — One cancer type per analysis Each SCART run must focus on a single cancer type. Do not mix, for example, lung cancer samples with ovarian cancer samples in the same run. If you have data from multiple cancer types, run SCART separately for each.
⚠️
Rule 3 — Make sure your conda environment is active Every command and script on this page assumes you have activated your scart_env conda environment. If you have not set it up yet, please complete the Installation guide first.

Reference Files — Where to Download

SCART uses two types of external reference files. You need to download these once and store them somewhere accessible on your computer or cluster.

🧬
Tabula Sapiens tissue references (for Modules 2 & 3)

These are tissue-specific healthy-cell references used for cell-type annotation (PopV) and malignant cell identification (SCEVAN). Download the file that matches your cancer type from the table below.
→ Download from Figshare: doi.org/10.6084/m9.figshare.27921984

🛡️
Healthy-tissue reference atlases (for Module 4)

Modules 4a and 4b assess safety — i.e., whether a candidate target gene is expressed in healthy tissues — against two independent healthy single-cell atlases: hpa_alltissues_geosketch_10k.h5ad (Human Protein Atlas) and tabula_sapiens_alltissues_10k.h5ad (Tabula Sapiens). These are not bundled with SCART or the GitHub repo — download whichever one(s) you plan to use from the SCART Zenodo record.
→ Download from Zenodo: (see SCART documentation for the record link)

You only need the file(s) for the atlas you're actually using — either one on its own is fine. Module 4 defaults to running against both and combining the results with Robust Rank Aggregation (RRA), but this is optional. See Module 4a below.

Scenario 1 — Using GEO Accession ID(s)

SCART downloads the data directly from NCBI GEO. You only need the GEO ID(s) and your reference files. This is the most common starting point.

What you need before starting

  • A GEO accession ID (format: GSExxxxxx). Find these on ncbi.nlm.nih.gov/geo.
  • The Tabula Sapiens reference file for your cancer type (download from Figshare — see table above).
  • The Module 4 healthy reference atlas file(s) — hpa_alltissues_geosketch_10k.h5ad and/or tabula_sapiens_alltissues_10k.h5ad (download from Zenodo — see above).
  • At least 20 GB free disk space and a stable internet connection for the download.
Variant A — Single GEO dataset (most common)

This example uses ovarian cancer dataset GSE158937. Replace the GEO ID, cancer_type, and file paths with your own values.

python
import SCART
from SCART.geo_fetcher import SampleAnnotator

# ── Step 1: Download & classify the GEO dataset ──────────────────────────
# USER: change "GSE158937" to your GEO ID
# USER: change cancer_type to match your cancer (see table above)
# USER: min_genes and max_mt are QC filters — adjust or remove if unsure
annotator = SampleAnnotator(
    "GSE158937",
    cancer_type="ovary_cancer",
    min_genes=200,    # cells with fewer than 200 genes are removed
    max_mt=40,        # cells with >40% mitochondrial reads are removed
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# After run() completes, SCART prints the recommended Tabula Sapiens
# reference filename for your cancer type. Download that file if you
# haven't already, then continue with Module 2 below.
print(f"Tumour samples found: {tumor}")
print(f"Output file: {query_h5ad}")
Variant B — Multiple GEO datasets merged

To combine data from several GEO datasets into one analysis, list all IDs as separate arguments. SCART merges them and saves a single combined_tumor.h5ad. This example uses two lung cancer datasets.

python
from SCART.geo_fetcher import SampleAnnotator

# USER: add or remove GEO IDs as needed — all must be the same cancer type
annotator = SampleAnnotator(
    "GSE184880",
    "GSE173682",
    cancer_type="lung_cancer",
    min_genes=200,
    max_mt=40,
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# Output: combined_tumor.h5ad (both datasets merged)
print(f"Output file: {query_h5ad}")
Variant C — Excluding specific samples (GSM IDs)

Some GEO datasets contain samples you do not want — for example, a CAR-T therapy study may include engineered CAR-T cell products alongside patient tumour samples. You can exclude any samples by their GSM ID. Tip: run without exclude_gsm_ids first to see the full sample list printed by SCART, then re-run with the IDs you want to drop.

python
from SCART.geo_fetcher import SampleAnnotator

annotator = SampleAnnotator(
    "GSE224550",
    cancer_type="blood_cancer",
    min_genes=200,
    max_mt=40,
    # USER: list the GSM IDs you want to exclude
    # Common use case: drop CAR-T cell product samples, keep patient PBMCs
    exclude_gsm_ids=[
        "GSM7025839", "GSM7025840",  # CAR-T product — patient P1
        "GSM7025847", "GSM7025848",  # CAR-T product — patient P2
    ],
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()
Variant D — Telling SCART what your batch is (batch_key)

By default, SCART uses the GSM ID (one value per GEO sample) as the batch for downstream batch correction — this is correct for most datasets, where one GSM = one library/capture run. If a GSM in your dataset actually contains multiple pooled patients or donors, GSM ID is too coarse. Pass batch_key with a keyword (e.g. "donor", "patient", "timepoint") and SCART will search each sample's GEO metadata for a matching field (e.g. "donor: P1") and save it as its own column.

python
from SCART.geo_fetcher import SampleAnnotator

annotator = SampleAnnotator(
    "GSE224550",
    cancer_type="blood_cancer",
    min_genes=200,
    max_mt=40,
    # USER: a keyword to search for in each GSM's GEO metadata (title /
    # source_name_ch1 / characteristics_ch1), e.g. "donor", "patient".
    # Only needed if one GSM in your GSE pools multiple donors/patients —
    # leave this out and GSM ID is used as the batch automatically.
    batch_key="donor",
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# SCART prints, per sample, whether "donor" was found in that GSM's
# metadata. Where found, it's saved as adata.obs["donor"]; where not
# found, that sample is tagged "unknown" for this column.
# Pass the SAME name to Module 2 next: batch_key="donor"
💡
Batch key — what SCART uses, and how to override it
If you don't set batch_key here (or in Module 2 below), GSM ID is used as the batch automatically — no configuration needed for the common case.

If GSM ID isn't right for your data (pooled multi-donor GSMs), you have two options:
1. Set batch_key='<keyword>' here (Variant D above) to try extracting it automatically from GEO sample metadata — works only for GEO ID input, not your own h5ad.
2. Supply your own h5ad with a batch column already in adata.obs, and pass its name as batch_key='<your column name>' directly to Module 2 (skips Module 1's extraction entirely).
✅
After completing Module 1 for any of the variants above, continue directly to Module 2 — Cell-Type Annotation.
②

Scenario 2 — Using Your Own h5ad File(s)

If you already have processed scRNA-seq data as a .h5ad file, you can supply it directly. The file must contain raw integer counts. Also covered: supplying your own cell-type labels to skip the PopV annotation step.

What you need before starting

  • Your .h5ad file(s) with raw (un-normalised) counts in adata.X or adata.layers['counts'].
  • The Tabula Sapiens reference file for your cancer type.
  • The Module 4 healthy reference atlas file(s) — hpa_alltissues_geosketch_10k.h5ad and/or tabula_sapiens_alltissues_10k.h5ad (download from Zenodo — see above).
  • (Optional) If you already have cell-type labels in your h5ad, the name of the column in adata.obs that holds them.
  • The name of your h5ad's own batch/donor column, if it has one — see the callout below.
💡
Your own batch column — batch_key on SampleAnnotator is a GEO-only feature (it searches GEO's own metadata text). It has no effect here, because SCART has no way to know what you named your batch/donor column in your own h5ad. If your file already has one, skip batch_key in Module 1 entirely and just pass that column's exact name straight to Module 2 instead: popv_annotation.auto_run_popv(..., batch_key='<your column name>'). If it has none, PopV falls back to no batch correction for these cells.
Variant A — Single h5ad file
python
from SCART.geo_fetcher import SampleAnnotator

# USER: replace the path with the location of your h5ad file
annotator = SampleAnnotator(
    "/path/to/my_data.h5ad",
    cancer_type="ovary_cancer",
    min_genes=200,
    max_mt=40,
    # No batch_key here — it's a GEO-only feature and has no effect on
    # your own h5ad. If your file has its own batch/donor column, pass
    # its name straight to Module 2 instead (see below).
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# Output: input_tumor.h5ad

# Then in Module 2, tell SCART your h5ad's OWN batch column name:
#   adata = popv_annotation.auto_run_popv(
#       user_reference = "...",
#       batch_key      = "donor",   # ← whatever column your h5ad already has
#   )
Variant B — Multiple h5ad files merged
python
from SCART.geo_fetcher import SampleAnnotator

# USER: list all h5ad files — they must all be the same cancer type
annotator = SampleAnnotator(

Variant C — h5ad with your own cell-type labels (skip PopV)

If your h5ad file already contains reliable cell-type annotations (from Seurat, CellTypist, or any other tool), you can skip Module 2 (PopV) entirely by providing the column name. Important: epithelial cell labels in your column must contain the text "epithelial cell" (case-insensitive) for Module 3 to detect them correctly. Examples of valid labels: epithelial cell, glandular epithelial cell, ovarian surface epithelial cell.

python
from SCART.geo_fetcher import SampleAnnotator

annotator = SampleAnnotator(
    "/path/to/my_annotated_data.h5ad",
    cancer_type="ovary_cancer",
    min_genes=200,
    max_mt=40,
    # USER: replace "cell_type" with the actual column name in your adata.obs
    manual_annotation_col="cell_type",
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# ✅ Skip Module 2 entirely — go straight to Module 3
⚠️
When using manual_annotation_col, your epithelial cell labels must contain the exact phrase "epithelial cell". Labels like "Epithelial" or "epithelial_cells" will not be recognised. SCART prints a warning if no epithelial cells are detected.
③

Scenario 3 — GEO ID + h5ad File Combined

You can mix GEO accession IDs and local h5ad files in the same run. SCART downloads the GEO data, loads the h5ad, and merges everything into one combined output.

⚠️
Batch key in a mixed run — batch_key here only extracts a value for the GEO-derived cells (by searching GEO metadata); your own h5ad's cells keep whatever columns they already had, completely untouched — SCART still doesn't know what you named them. If you don't set anything, the GEO cells get gsm_id/gse_id while your h5ad's cells have neither, so those rows end up with no batch value after combining. For one clean, unified batch column across both sources: give your own h5ad a batch/donor column first, then pass that same name as batch_key='<name>' to both this SampleAnnotator call (so the GEO side gets it extracted from metadata too) and to Module 2.
python
from SCART.geo_fetcher import SampleAnnotator

# Mix GEO IDs and h5ad paths freely — all must be the same cancer type
annotator = SampleAnnotator(
    "GSE158937",                     # downloaded from GEO
    "/path/to/extra_data.h5ad",      # your own local file — MUST already have
                                            # its own "donor" column for this to line up
    cancer_type="ovary_cancer",
    min_genes=200,
    max_mt=40,
    # USER: only meaningful if your own h5ad ALSO already has a column
    # with this exact name — otherwise those rows get no batch value.
    batch_key="donor",
)
normal, tumor, unspecified, annotation_info, query_h5ad, cancer_type, results = annotator.run()

# Output: combined_tumor.h5ad

# Pass the SAME name to Module 2 next:
#   adata = popv_annotation.auto_run_popv(..., batch_key="donor")

Pipeline Steps — Overview

Regardless of which input scenario you used, all five modules run in the same order. Each module automatically detects the output of the previous one — you do not need to manually pass file paths between steps (unless you want to use custom locations).

StepWhat it doesOutput fileTypical time
Module 1Downloads / loads data, classifies tumour vs normal samples, applies QC*_tumor.h5ad5–30 min
Module 2Annotates cell types using PopV consensus frameworkfinal_popv_annotated.h5ad30–120 min
Module 3Identifies malignant epithelial cells (SCEVAN + scMalignantFinder); runs DEG (malignant vs. rest) and a Harmony-integrated tumour-vs-healthy-reference Cancer Composition Score; keeps genes common to all three: DEG ∩ Cancer Composition (z-score ≥ 0.5) ∩ surfaceome listfinal_tumor.h5ad45–210 min
Module 4aScores every candidate surface gene for efficacy and safety against one or both healthy atlasesfinal_single_gene_candidates_RRA_HPA_Tabula.csv5–15 min
Module 4bFinds optimal two-gene pairs using a genetic algorithm with AND / OR / NAND logic gates, against one or both healthy atlasesfinal_candidates_RRA_HPA_Tabula.csv30–240 min

Module 2 — Cell-Type Annotation (PopV)
Skip this step if you used manual_annotation_col in Module 1

PopV runs multiple annotation methods in parallel (CELLTYPIST, KNN-SCVI, SCANVI, and others) and reports a majority-vote cell-type prediction for each cell. Module 1 prints the name of the Tabula Sapiens reference file recommended for your cancer type — download that file before running this step.

💡
Batch key default — if you don't pass batch_key below (and didn't set it in Module 1), GSM ID is used as the batch automatically. If GSM ID isn't valid for your data (e.g. pooled multi-donor GSMs), either re-run Module 1 with batch_key='<keyword>', or pass batch_key='<your column name>' here directly.
ParameterStatusDefaultWhat to change
nsamplesoptional300Cells sampled per label from reference. Increase for better accuracy, decrease to save memory.
user_referencerequired—Path to the Tabula Sapiens tissue reference file for your cancer type. Download from Figshare — see the cancer type table above for the exact filename.
output_diroptional"popv_results"Where to save the annotated h5ad. Change if you want a custom location.
batch_keyoptionalauto-detected (gsm_id first)Column in your query h5ad's .obs to use as the batch key. Defaults to GSM ID for GEO-derived data. Set this to match whatever batch_key you used in Module 1, or to your own h5ad's batch column name.
seedoptional0Random seed for reproducibility. Seeds python's and numpy's global RNG before annotation, and is also passed to PopV's own methods if your installed PopV version accepts a seed there. Change only if you specifically want a different run's randomness.
python
from SCART import popv_annotation

# Recommended: supply the Tabula Sapiens reference file you downloaded
# USER: replace the path with the actual location of your reference file
adata = popv_annotation.auto_run_popv(
    nsamples       = 300,
    user_reference = "/path/to/Ovary_TSP1_30_version2d_10X_smartseq_scvi_Nov262024.h5ad",
    # batch_key not set → GSM ID used as batch automatically.
    # If you passed batch_key="donor" in Module 1 (or your own h5ad
    # has a "donor" column), uncomment this to match it:
    # batch_key = "donor",
    seed = 0,  # reproducible by default — change only if you want different randomness
)

# Inspect the annotation results
print(adata.obs["popv_majority_vote_prediction"].value_counts())

# Output saved automatically to: popv_results/final_popv_annotated.h5ad
3
Module 3 — Malignant Cell Identification & Surfaceome DE
Requires the same Tabula Sapiens reference used in Module 2

Module 3 identifies high-confidence malignant epithelial cells using two independent tools (scMalignantFinder and SCEVAN) and then narrows candidate surface genes down using three independent criteria run in parallel, keeping only genes that pass all three: (1) standard DEG — malignant epithelial vs. the non-epithelial "rest" of the same sample (Wilcoxon, log2FC/adjusted p-value); (2) a Cancer Composition Score — malignant cells vs. an external healthy reference (the same Tabula Sapiens file used above), Harmony-integrated to remove batch effects, scored per gene by how much more often it's detected in tumour cells than healthy cells; and (3) surfaceome membership (the GESP list). The "intersection" strategy for malignant calling — requiring both tools to agree — is strongly recommended for maximum specificity.

💡
Cancer Composition Score — alongside the standard DEG test, Module 3 Harmony-integrates your malignant cells with a healthy reference dataset and computes a per-gene "Cancer Composition Score" (how much more a gene is detected in tumour cells vs. healthy cells, expressed as a difference of z-scores). Genes are only kept in the final output if they pass this score and the DEG test and are on the surfaceome list — not any one of the three alone. This step always reuses the same reference_h5ad you already provide above — there's no separate file to download or path to configure. It also saves a before/after UMAP plot (unintegrated vs. Harmony-integrated) so you can visually confirm the integration worked.

from SCART import preprocessing

# USER: replace the reference path with your Tabula Sapiens file
adata_preprocessed = preprocessing.run_preprocessing_pipeline(
    reference_h5ad     = "/path/to/Ovary_TSP1_30_version2d_10X_smartseq_scvi_Nov262024.h5ad",
    log2fc_threshold   = 2.0,
    pval_adj_threshold = 0.05,
    malignant_strategy = "intersection",
    scevan_ref_max_cells = 100,

Module 4a — Single-Gene CAR-T Target Scoring
Requires the Module 4 healthy atlas file(s) downloaded from Zenodo

Module 4a scores every surface gene identified in Module 3 for two properties: Efficacy (how well the gene distinguishes tumour cells) and Safety (how absent the gene is from healthy tissue). Higher is better for both. Safety can be checked against either healthy atlas alone, or — recommended — against both independently, with the two ranked gene lists then combined via Robust Rank Aggregation (RRA) so a candidate only counts as "safe" once two independent references agree.

💡
You only need to download and supply the atlas file you're actually using. Set atlas="hpa" with just hpa_path=, or atlas="tabula" with just tabula_path= — the other path argument is not required and can be left out entirely. Both files (and both path arguments) are only needed when atlas="both".

Module 4b — Two-Gene Logic-Gate Scoring
Searches for optimal gene pairs using a genetic algorithm

Module 4b extends the single-gene analysis to pairs of genes, evaluated with three logic gates: A & B (both expressed), A | B (either expressed), and A &! B (A expressed, B not expressed — NAND gate for safety). A genetic algorithm efficiently searches the combination space. Like Module 4a, it can score safety against either healthy atlas alone, or — recommended, and the default — against both independently, combining the two ranked candidate-pair lists via Robust Rank Aggregation (RRA).

python — Module 3 · Malignant Cell Identification
from SCART import preprocessing

adata_preprocessed = preprocessing.run_preprocessing_pipeline(

    reference_h5ad="/path/to/Ovary_TSP1_30_version2d_10X_smartseq_scvi_Nov262024.h5ad",
                           # ← CHANGE: same Tabula Sapiens file used in Module 2.
                           #   This is used to build a healthy reference for SCEVAN,
                           #   which detects copy number variations to identify
                           #   malignant cells.

    malignant_strategy="intersection",
                           # ← RECOMMENDED: "intersection" means BOTH scMalignantFinder
                           #   AND SCEVAN must agree that a cell is malignant.
                           #   This gives the highest confidence results — fewer false
                           #   positives, better CAR-T targets downstream.
                           #
                           #   Alternatives (use only if you have a specific reason):
                           #   "scMalignant" — use scMalignantFinder only (no SCEVAN).
                           #     Use if you do not have a Tabula Sapiens reference or
                           #     want a faster run. Less specific than intersection.
                           #   "scevan"       — use SCEVAN only.

    log2fc_threshold=2.0,  # ← Minimum fold-change a gene must show between malignant
                           #   and non-malignant cells to be called differentially
                           #   expressed (and thus a candidate CAR-T target).
                           #   log2FC of 2.0 means the gene is expressed ~4× higher
                           #   in tumour cells — a stringent, sensible default.
                           #   Increase (e.g. 3.0) for a shorter, higher-confidence
                           #   target list. Decrease (e.g. 0.5–1.0) if you are getting
                           #   very few candidates and want to cast a wider net.

    pval_adj_threshold=0.05,
                           # ← Maximum adjusted p-value for a gene to be included.
                           #   0.05 is the standard statistical significance cutoff
                           #   (5% false discovery rate). Only change this if you
                           #   have a specific statistical reason — 0.05 is almost
                           #   always appropriate.

    scevan_ref_max_cells=100,
                           # ← Maximum number of healthy reference cells given to
                           #   SCEVAN per run. 100 is a conservative, memory-safe
                           #   default that works on most machines.
                           #   Increase to 200–500 if you have 32+ GB RAM — a larger
                           #   reference gives SCEVAN a more stable baseline, which
                           #   can improve malignant cell detection accuracy.
                           #   Decrease if SCART runs out of memory.

    scevan_par_cores=1,    # ← CPU cores used by SCEVAN. Set this to the number of
                           #   cores available on your machine to speed things up.
                           #   On a standard laptop: 4. On a workstation: 8–16.
                           #   On HPC: match to --cpus-per-task in your SLURM script.

    scevan_batch_size=3000,
                           # ← How many tumour cells are processed per SCEVAN batch.
                           #   3000 works for most machines with ≥16 GB RAM.
                           #   Decrease (e.g. 1000–1500) if you run out of memory.
                           #   Increase (e.g. 5000) if you have 64+ GB RAM and want
                           #   fewer, faster batches.

    scevan_organism="human",
                           # ← Set to "mouse" if your data is from mouse samples.
                           #   Leave as "human" for all human cancer data.

    scevan_sample_name="SCEVAN_run",
                           # ← A label used as a prefix for SCEVAN's output files.
                           #   You can change this to anything descriptive, e.g.
                           #   "GSE158937_ovary". It does not affect results.

    scevan_subclones=False,
                           # ← Whether SCEVAN should try to detect tumour subclones
                           #   (genetically distinct sub-populations within the tumour).
                           #   False is faster and sufficient for CAR-T target discovery.
                           #   Set to True only if you specifically want subclone
                           #   information — it significantly increases run time.

    # ── Cancer Composition Score (Step 8b) ────────────────────────────────
    # Alongside the DEG test above (malignant vs. the rest of the same
    # sample), Module 3 also Harmony-integrates your malignant cells
    # with reference_h5ad (the SAME file you already gave above — no second
    # file to download or configure) and scores every gene by how much more
    # it's detected in tumour cells than in that healthy reference. The
    # FINAL gene list kept in the output is genes common to ALL THREE:
    # DEG-passing ∩ Cancer-Composition-passing ∩ surfaceome list.
    # This runs automatically — nothing below is required to turn it on.

    cc_score_threshold=0.5,
                           # ← Minimum Cancer Composition Score (Tumour_Z − Healthy_Z)
                           #   for a gene to pass this criterion.
                           #   0.5  → standard, balanced (recommended)
                           #   1.0+ → stricter, fewer but more tumour-preferential genes
                           #   0.0–0.3 → lenient, more candidates pass

    # --- Optional overrides for this step (defaults are fine for almost
    #     every run — only uncomment if you know you need to) ---
    # run_cancer_composition=True,  # set False to skip this step entirely
    #                                # and fall back to DEG ∩ surfaceome only
    # cc_n_top_genes=3000,        # HVGs used to build the Harmony/UMAP embedding
    # cc_n_pcs=50,                # PCA dimensions passed into Harmony
    # cc_max_iter_harmony=10,     # Harmony's max clustering iterations
    # cc_theta=None,              # Harmony diversity penalty (None = harmonypy default, 2.0)
    # cc_seed=0,                  # random seed, for reproducibility
    # cc_tumor_batch_key=None,    # auto-detected (gsm_id / sample / batch / donor, …)
    # cc_healthy_batch_key=None,  # auto-detected (donor / gsm_id / sample / batch, …)
)

Step 4a — Single-gene CAR-T target scoring

python — Module 4a · Single-Gene Scoring
from SCART.gene_combination_predictor import one_gene_combination

result = one_gene_combination.run(

    atlas="both",           # ← Which healthy atlas(es) to score safety against.
                           #   "both"   → runs against HPA AND Tabula Sapiens
                           #   independently, then combines the two ranked gene
                           #   lists via Robust Rank Aggregation (RRA). Returns a
                           #   dict — see below. Default, and recommended: a gene
                           #   only counts as "safe" once it has been checked
                           #   against two independent healthy references.
                           #   "hpa"    → HPA only. Returns a single DataFrame.
                           #   "tabula" → Tabula Sapiens only. Returns a single DataFrame.

    hpa_path="/path/to/hpa_alltissues_geosketch_10k.h5ad",
                           # ← CHANGE: path to your local copy of
                           #   hpa_alltissues_geosketch_10k.h5ad, downloaded from
                           #   Zenodo (see Reference Files section above — NOT
                           #   bundled with SCART). Needed when atlas="hpa" or
                           #   "both". If omitted, SCART looks for this exact
                           #   filename in the current directory and
                           #   ./healthy_atlases/.

    tabula_path="/path/to/tabula_sapiens_alltissues_10k.h5ad",
                           # ← CHANGE: path to your local copy of
                           #   tabula_sapiens_alltissues_10k.h5ad, downloaded from
                           #   Zenodo. Needed when atlas="tabula" or "both". Same
                           #   auto-detection rule as hpa_path.

    safety_threshold=0.9, # ← The minimum fraction of healthy cell types that must
                           #   NOT express this gene for it to be considered safe,
                           #   applied independently within each atlas.
                           #   0.9 = the gene must be absent from at least 90% of
                           #   healthy tissues — the recommended default.
                           #
                           #   0.95 → very strict, fewer candidates, lower off-tumour
                           #          risk, good for clinical prioritisation
                           #   0.90 → standard, balanced (recommended)
                           #   0.80 → lenient, more candidates, higher off-tumour risk
                           #          use only for exploratory analysis

    rra_efficacy_threshold=0.7,
                           # ← Only used when atlas="both". A gene must clear this
                           #   efficacy threshold in BOTH atlases to be eligible
                           #   for the final RRA-combined ranking. 0.7 recommended.

    rra_safety_threshold=0.9,
                           # ← Only used when atlas="both". A gene must clear this
                           #   safety threshold in BOTH atlases to be eligible for
                           #   the final RRA-combined ranking. 0.9 recommended.
)

# atlas="both" returns a dict; atlas="hpa"/"tabula" returns a single DataFrame
if isinstance(result, dict):
    df_hpa    = result["hpa"]      # full results, HPA only
    df_tabula = result["tabula"]   # full results, Tabula Sapiens only
    df_rra    = result["rra"]      # RRA-combined ranking — the headline result

    print("Top 10 — HPA only:")
    print(df_hpa.sort_values("Efficacy", ascending=False).head(10))

    print("\nTop 10 — Tabula Sapiens only:")
    print(df_tabula.sort_values("Efficacy", ascending=False).head(10))

    print("\nTop 10 — RRA-combined (safe + effective in BOTH atlases):")
    print(df_rra.head(10))
else:
    # atlas="hpa" or atlas="tabula" — single-atlas run, single DataFrame back
    top = result[result["Safety"] >= 0.9].sort_values("Efficacy", ascending=False)
    print(top.head(20))

Step 4b — Two-gene logic-gate CAR-T target scoring

This module searches for optimal pairs of genes, tested with three logic gates: A & B (target cells expressing both genes), A | B (expressing either), and A &! B (expressing A but not B — useful for safety, since a healthy-tissue marker can be used as an exclusion signal). A genetic algorithm efficiently explores millions of possible pairs.

python — Module 4b · Two-Gene Combination Scoring
from SCART.gene_combination_predictor import two_gene_combination

result = two_gene_combination.run(

    atlas="both",           # ← Same meaning as Module 4a: "hpa" / "tabula" / "both".
                           #   "both" runs the full GA search independently against
                           #   each atlas, then combines the two ranked candidate-pair
                           #   lists via Robust Rank Aggregation (RRA).

    hpa_path="/path/to/hpa_alltissues_geosketch_10k.h5ad",
                           # ← CHANGE: same file as Module 4a. Needed for atlas="hpa"/"both".

    tabula_path="/path/to/tabula_sapiens_alltissues_10k.h5ad",
                           # ← CHANGE: same file as Module 4a. Needed for atlas="tabula"/"both".

    safety_threshold=0.9, # ← Same meaning as Module 4a. Applied as the GA fitness
                           #   cutoff inside each atlas's own search. 0.9 recommended.

    rra_efficacy_threshold=0.7,
    rra_safety_threshold=0.9,
                           # ← Only used when atlas="both". A candidate pair must
                           #   clear both thresholds in BOTH atlases to enter the
                           #   final RRA-combined ranking. Defaults match Module 4a.

    pop_size=1000,         # ← Number of gene pairs in each "generation" of the
                           #   genetic algorithm. Think of it as the population size
                           #   in an evolutionary search — larger means the algorithm
                           #   explores more of the search space per generation.
                           #   200  → fast test run (laptop / first look)
                           #   1000 → standard run (recommended)
                           #   2000 → thorough run (HPC, large gene lists)

    Gmax=100,              # ← Maximum number of generations the algorithm is allowed
                           #   to run. More generations = more optimisation time.
                           #   In practice the algorithm often stops early (see patience).
                           #   20  → quick test
                           #   100 → standard (recommended)
                           #   200 → thorough (HPC)

    patience=50,           # ← Early stopping: if the best score has not improved for
                           #   this many consecutive generations, the algorithm stops.
                           #   This saves time when results have converged.
                           #   10  → stops quickly, may miss small improvements
                           #   50  → standard balance (recommended)
                           #   100 → keeps running longer, for thorough HPC runs

    n_jobs=None,            # ← Parallel workers across seeds (joblib). Defaults to
                           #   n_runs (one worker per seed) — this is the single
                           #   biggest speed lever for Module 4b.
                           #   Lower this if n_runs exceeds your available CPU cores,
                           #   e.g. n_jobs=4 on a laptop, n_jobs=8 on a workstation,
                           #   n_jobs=16-40 on an HPC node.

    n_runs=10,             # ← Number of independent algorithm runs with different
                           #   random starting points. Because genetic algorithms have
                           #   a random component, running multiple times and combining
                           #   results gives more robust and reproducible output.
                           #   2   → quick test only
                           #   10  → standard, reliable (recommended)
                           #   10+ → diminishing returns beyond 10 for most datasets

    # --- Island-model GA configuration (defaults match the reference script) ---
    # n_islands=4,          # number of islands the population is split across
    # migrate_interval=10,  # generations between ring-migration events
    # migrate_k=10,         # individuals migrated per island per event
    # and_quota_frac=0.25,  # share of pop_size pre-seeded as "A & B" individuals
    # nand_quota_frac=0.25, # share of pop_size pre-seeded as "A &! B" individuals
    # gate_min_frac=0.20,   # minimum share of each gate type kept through selection
    # mutpb=0.30,           # mutation probability applied each generation
    # sbx_eta=2.0,          # SBX crossover distribution index
)

# atlas="both" returns a dict; atlas="hpa"/"tabula" returns (df_hof, df_all)
if isinstance(result, dict):
    df_hof_hpa,    df_all_hpa    = result["hpa"]      # full results, HPA only
    df_hof_tabula, df_all_tabula = result["tabula"]   # full results, Tabula Sapiens only
    df_rra                       = result["rra"]      # RRA-combined ranking — the headline result

    print("Top 10 — HPA only:")
    print(df_hof_hpa.head(10))

    print("\nTop 10 — Tabula Sapiens only:")
    print(df_hof_tabula.head(10))

    print("\nTop 10 — RRA-combined (safe + effective in BOTH atlases):")
    print(df_rra.head(10))
else:
    # atlas="hpa" or atlas="tabula" — single-atlas run, (df_hof, df_all) back
    df_hof, df_all = result

    # View the best AND-gate pairs (both genes must be expressed on tumour cell)
    and_pairs = df_hof[df_hof["LogicGates"] == "A & B"]
    print("Top AND-gate pairs:"); print(and_pairs.head(10))

    # View the best NAND-gate pairs (tumour expresses A but NOT B —
    # B acts as a "safety catch" to spare healthy cells that express B)
    nand_pairs = df_hof[df_hof["LogicGates"] == "A &! B"]
    print("Top NAND-gate pairs:"); print(nand_pairs.head(10))

#   two_gene_complete_hpa.csv / two_gene_hof_hpa.csv       → per-atlas full results
#   two_gene_complete_tabula.csv / two_gene_hof_tabula.csv → per-atlas full results
#   final_candidates_RRA_HPA_Tabula.csv                    → RRA-combined ranking

Using only one atlas — same idea as Module 4a: set atlas="hpa" or atlas="tabula" and drop the other *_path argument. This skips the second GA run and RRA entirely, and run() returns a plain (df_hof, df_all) tuple, e.g.: 
df_hof, df_all = two_gene_combination.run(
    atlas    = "hpa",
    hpa_path = "/path/to/hpa_alltissues_geosketch_10k.h5ad",
    safety_threshold = 0.9,
    pop_size = 1000, Gmax = 100, patience = 50, n_runs = 10,
)
